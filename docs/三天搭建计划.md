# MoonStep 前三天搭建计划

> 黑客松提前启动版 · 2026-09-28

---

## Day 1：地基日 — 项目初始化 + Moonpad 跑通 + 基础布局

**目标**：项目骨架搭起来，编辑器能跑、能编译、能看到输出。

| 时段 | 任务                  | 交付物                                         | 验收标准                                               |
| ---- | --------------------- | ---------------------------------------------- | ------------------------------------------------------ |
| 上午 | 项目初始化 + 构建配置 | `package.json`、`esbuild.js`、`.gitignore`     | `npm install` 成功，esbuild 能打包                     |
| 上午 | Moonpad 集成          | `vendor/moonpad/` 静态资源 + 编辑器封装模块    | 页面上能看到 Monaco 编辑器，MoonBit 语法高亮正常       |
| 下午 | 编译运行打通          | 运行按钮 + 控制台输出面板                      | 输入 `println("hello")` 点运行，控制台正确输出 `hello` |
| 下午 | 整体布局框架          | 三栏布局（左侧教程 + 中间编辑器 + 右侧控制台） | 深色主题、月兔黄点缀、玻璃拟态卡片、响应式基础         |
| 晚上 | 主题系统 + 基础动效   | CSS 变量主题、页面入场动画                     | 深色模式下视觉协调，有基本过渡动效                     |

**技术要点**：

- esbuild 打包，输出到 `dist/`
- Moonpad worker 资源正确配置路径
- 布局用 CSS Grid，移动端做最基本的适配（至少不崩）
- 用 CSS 变量定义月兔黄色系：`#fef3c7 → #fbbf24 → #d97706`

---

## Day 2：核心日 — 关卡系统 + 验证器 + 单关完整流程 + 进度保存

**目标**：一个完整的关卡能从头走到尾（学 → 写 → 跑 → 通过 → 解锁下一关）。

| 时段 | 任务                  | 交付物                                     | 验收标准                                             |
| ---- | --------------------- | ------------------------------------------ | ---------------------------------------------------- |
| 上午 | 关卡数据格式 + 加载器 | `levels/01-variables.json` + 关卡加载模块  | JSON 配置能正确加载到页面上                          |
| 上午 | 教程面板 UI           | 左侧教程内容渲染、章节切换                 | 支持 Markdown 级别的文字排版、代码块、提示块         |
| 下午 | 题目验证器            | `validator.js`（stdout 匹配 + 多测试用例） | 对的代码判通过，错的代码判失败                       |
| 下午 | 反馈系统              | 成功/失败动画、错误信息高亮、提示按钮      | 编译失败有红波浪，测试失败有明确差异，通过有庆祝效果 |
| 晚上 | 进度系统              | `progress.js`（localStorage 读写）         | 刷新页面进度不丢，已通关卡显示完成状态               |
| 晚上 | 第一关内容打磨        | 变量关 3-4 个小节 + 挑战题                 | 新手能跟着走通，有学习曲线                           |

**技术要点**：

- 关卡配置格式要设计好，为以后扩展留空间
- 验证器要支持多种验证策略（不只是 stdout 匹配）
- 进度数据结构：`{ completedLevels: {}, currentLevel: '', achievements: [] }`

## Day 3：丰满日 — 关卡地图 + 多关卡 + 成就雏形 + 适配优化

**目标**：从"一道题"变成"一个产品"，有地图、有多个关卡、有基本的完成感。

| 时段 | 任务              | 交付物                       | 验收标准                                             |
| ---- | ----------------- | ---------------------------- | ---------------------------------------------------- |
| 上午 | 关卡地图页面      | `level-map.js` + 地图 UI     | 节点式地图，已完成/进行中/未解锁三种状态             |
| 上午 | 路由/页面切换     | 首页 → 地图 → 关卡页         | 页面切换有过渡动画，状态正确                         |
| 下午 | 补齐 3-4 个关卡   | 函数关、模式匹配关、结构体关 | 每关至少 2-3 个练习点                                |
| 下午 | 成就系统雏形      | `achievements.js` + 徽章展示 | 首胜、全优等基础徽章能触发和展示                     |
| 晚上 | 兼容性 & 适配     | 浏览器测试 + 响应式优化      | Chrome / Edge / Firefox 正常，13寸到 27 寸屏幕都好看 |
| 晚上 | 代码重置 + 快捷键 | 重置按钮、Cmd+R 运行         | 基本交互顺手                                         |

**技术要点**：

- 关卡地图用纯 CSS + JS 实现，不要用 canvas，保持轻量
- 页面切换动画：从左滑入 + 模糊渐显，不要千篇一律淡入淡出
- 适配优先保证桌面端（1280px+），平板次之，手机最低限度可用

## 开发约定

- **提交规范**：Conventional Commits（`feat:` `fix:` `style:` `refactor:` `docs:`）
- **分支策略**：直接在 `main` 上开发，小步提交
- **代码风格**：原生 JS 优先，能不引库就不引
- **注释**：关键逻辑加注释，复杂算法写清楚思路
